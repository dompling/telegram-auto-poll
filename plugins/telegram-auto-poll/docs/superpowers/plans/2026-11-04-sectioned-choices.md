# Sectioned choice regression

Problem: v0.2.1 misses real installation decisions with A/B/C headings separated by explanations and commands. The selection phrase “你选哪条路” is absent from the matcher, and a promise after the final question hides that question.

Approach: Keep the existing explicit POLL parser and delivery lifecycle. Extend the bounded text detector to recognize common selection phrases, extract a terminal question followed by prose on the same line, and associate a single ordered A/B/C section group with a selection prompt. Use complete section titles as ballot labels and preserve the original message as the introduction. Keep sequential steps, examples, quotes, hidden code, ambiguous groups, free input, duplicate labels and size limits excluded. Do not guess missing alternatives or use another model/dependency.

Alternatives: Prompt-only changes still fail when the model omits POLL. Treating every list as a ballot would reintroduce diagnostic-list false positives. Use explicit section labels and a selection prompt instead.

Verification: Preserve the reported message as a fixture. First reproduce detector and delivery failures, plus related heading, wording and trailing-prose variants. Cover exclusions and ambiguous/incomplete groups. Implement the minimal detector change, run the full test suite, syntax/static diff checks and isolated host loader when available. Review the diff, update package/plugin/README to v0.2.2, then publish the verified repair to the existing public repository. No production configuration changes or Telegram messages are part of this repair.

Progress: The initial fixture/wording/delivery tests reproduced five failures.
