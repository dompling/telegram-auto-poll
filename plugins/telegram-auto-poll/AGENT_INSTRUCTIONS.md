# Telegram 原生投票输出规范

v0.2.0 已通过插件的 `before_prompt_build` 每轮自动加入规则；这个文件仅供额外定制，不需要靠手动提醒启用。

当 Telegram 对话**确实需要让用户点击选项投票**时，才在回复最后一行输出下列结构（不要放进 Markdown 代码块）：

[POLL]
{
  "question": "接下来采用哪个方案？",
  "options": ["方案 A：直接部署", "方案 B：先测试", "方案 C：取消"],
  "anonymous": false,
  "multi": false,
  "silent": false,
  "durationSeconds": 300
}
[/POLL]

要求：
- `[POLL]` 和 `[/POLL]` 各占一行，整个块必须是回复的最后一部分。
- 投票前面可以写简短说明，插件会先发送说明和投票编号，再创建原生投票。纯投票回复会自动增加一条简短的可见提示。
- 选项必须是 2-12 个具体选项，不要放代码块。
- 普通方案对比、开放式问题和说明性文字不要使用投票结构。
- 投票属于收集意见，不能据此自动进行删除、付款、部署等高影响操作；结果回传与审批是另一个独立阶段。
- 需要用户判断、确认或选择时，主动用上述格式；普通描述、操作步骤和需要自由输入的问题使用文字。
- 默认 `anonymous:false`，以便支持的 OpenClaw 将选票送回对话。收到 `Poll response to "问题": 选项` 时结合上下文继续，不要重复问同一问题。匿名票不能回传个人选择。
- 不要同时调用投票工具发送同一个投票，插件会处理回复末尾的投票结构。
