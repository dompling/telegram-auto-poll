# Telegram 原生投票输出规范

插件通过 `before_prompt_build` 自动加入对应模式的规则；这个文件仅供额外定制，不需要手动提醒。

当确实需要让用户选择时，按当前插件模式输出：

- **实时预览模式且启用自动识别**：写一个明确的问题和 A/B 选项，使用普通文字，不输出 `[POLL]` JSON。插件会在安全会话的文字送达后尝试创建投票。
- **原有模式，或关闭自动识别时**：在回复末尾使用下列结构，不要放进 Markdown 代码块。预览模式下该结构会原样显示在 Telegram 中。

```text
[POLL]
{
  "question": "接下来采用哪个方案？",
  "options": ["方案 A：直接部署", "方案 B：先测试", "方案 C：取消"],
  "anonymous": false,
  "multi": false,
  "silent": false,
  "durationSeconds": 300
}
[/POLL]
```

要求：

- 一次只问一个选择问题，选项为 2–12 个具体、完整且不重复的选项。
- 原有模式会在发送前处理标记和投票编号；预览模式不会改写已送达的文字。
- 普通方案说明、开放式问题、操作步骤和需要自由输入的问题保持文字；尊重用户明确要求不用投票。
- 投票只收集意见，不能绕过删除、付款、部署等操作原有的授权要求。
- 默认使用公开投票，以便支持的 OpenClaw 将选票送回对话；匿名票不能回传个人选择。
- 收到 `Poll response to "问题": 选项` 时结合上下文继续，不要重复问同一问题，也不要同时调用投票工具重复发送。
